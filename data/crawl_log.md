## 二、成功渠道的技术细节

### 1. App Store 中国区（主证据源）

原计划走苹果公开的评论 RSS 接口，实测已失效：

```
GET https://itunes.apple.com/cn/rss/customerreviews/id=6459478672/sortBy=mostRecent/json
→ 返回 200，但 feed 中无任何 entry（苹果已停止该接口的评论下推）
```

改用仍可用的遗留接口：

```
GET https://itunes.apple.com/WebObjects/MZStore.woa/wa/userReviewsRow
      ?id=<appId>&displayable-kind=11&page=1&sort=<1-8>&appVersion=all
Headers: X-Apple-Store-Front: 143465-19,29
```

**该接口的关键限制**：`page` 参数**不生效**——page=1 到 page=30 返回完全相同的 10 条。因此横向扩展的唯一办法是**遍历 sort 维度**（sort=1…8 各自返回不同的 10 条），实测每个 App 可稳定获得 30–38 条去重后的唯一评论。

采集范围：豆包主 App、豆包爱学、豆包输入法，以及 DeepSeek、千问、Kimi、元宝、文心 5 款竞品。

### 2. 豌豆荚（安卓应用商店）

`https://www.wandoujia.com/apps/com.larus.nova/comment` 的评论是服务端渲染的，可直接解析 `li.normal-li` 结构。但 `?page=N` 参数同样不生效，首屏固定 10 条，页面标注总数 99 条但无可用翻页入口。

该渠道的评分只有"推荐 / 不推荐"二元选项，入库时按 5★ / 1★ 折算（已在 `comments.csv` 的 `note` 字段标注）。

### 3. B站（社交渠道 · 唯一探通）

B站是本次唯一未被风控直接拒绝的社交渠道。搜索与评论两个接口都在**页面上下文内 fetch**（浏览器自动携带主站 cookie，同源 CORS 放行）：

```
搜索：GET https://api.bilibili.com/x/web-interface/search/type
          ?search_type=video&keyword=<kw>&page=<n>
评论：GET https://api.bilibili.com/x/v2/reply?type=1&oid=<aid>&pn=1&ps=20&sort=2
```

采集结果：8 个关键词 × 2 页 → 245 个视频（去重）→ 标题含「豆包」208 个 → 实际抓到一级评论 **74 条**（仅 31 个视频有评论产出）→ 清洗后 66 条 → **人工复核后纳入分析 22 条**。

**该渠道的关键限制（全部为实测）**：

| 试探的端点 | 实测结果 |
|---|---|
| `x/v2/reply` pn=1 sort=2 | `code:0`，返回 **3 条** |
| `x/v2/reply` pn=2 sort=2 | `code:0`，返回 **0 条** |
| `x/v2/reply/main` mode=3 next=0 | 返回 3 条，`is_end=true`，但 `all_count=10607` |
| `x/v2/reply/main` next=1 | 返回 0 条 |
| `x/v2/reply/wbi/main`（wbi 签名已正确实现，`mixin_key` 已算出） | `code:-403 访问权限不足`，需登录态 |
| 累计约 160 次请求后 | 响应体由 JSON 变为 HTML，返回 **HTTP 412 风控页**；退避 25s 连续重试仍为 412 → IP 级临时封禁 |

结论：**B站对未登录访客硬性封顶，每条视频只返回 3 条"最热"评论**，且返回的是点赞最高的评论（偏梗化）。样本量因此由"视频覆盖面"决定，而覆盖面又受风控封顶约束。这一限制使 B站 样本不具备统计代表性，只能做定性旁证。

采集与判定过程留档：`data/bili/bili_all_raw.json`（原始）、`data/bili/bili_clean_stats.md`（漏斗与剔除原因）、`data/bili/relevance_review.md`（66 条逐条纳入/排除理由）、`data/bili/tags_bili.txt`（打标）、`data/bili/stats_bili.md`（统计与局限）。

## 三、失败渠道的技术细节与结论

| 渠道 | 卡在哪 | 是否有替代路径 |
|---|---|---|
| 黑猫投诉 | 首页正常（9,882 字符），但 `/search/?keywords=豆包` 返回空 DOM（2 字符）；其 API `/api/index/feed` 需要客户端生成的 `signature` 参数 | 有：需先逆向签名逻辑，或走 App 端接口。本次未做 |
| 应用宝 | 页面为纯 SPA，Network 中无任何 XHR，`document.body.innerText` 仅 51 字符 | 未知：可能需要 App 端协议 |
| 小米应用商店 | 页面正常渲染但注明"维护中"，评论区入口不可用 | 有：等维护结束或走 App 接口 |
| 华为应用市场 | 未拿到豆包的正确 appID | 有：可从华为网页版搜索页重新定位 |
| 小红书 | IP 存在风险（错误码 300012），直接拒绝服务 | 有：需更换网络出口或走 App 端 |
| 抖音 | 跳转"验证码中间页"，`verify.snssdk.com` 验证组件加载 | 有：需登录态 + 人工过验证码 |
| 百度贴吧 | 跳转"百度安全验证"，要求滑块拼图 | 有：需人工过验证码，或使用已登录的浏览器 profile |
| 知乎 | 接口返回 403 风控（`code 40362`） | 有：需登录态；帖子详情页可能比搜索页宽松 |
| B站 | 页面与接口均无风控障碍，但**未登录访客每条视频上限 3 条评论**（见二·3） | 已采集：74 条原始 / 22 条纳入分析。要扩大规模唯一路径是提供登录态（有账号风险，未采用） |

**结论**：本次分析的主证据来自 App Store + 豌豆荚，属于"应用商店评论"这一类渠道。社交媒体渠道中**只有 B站 拿到了可用评论**（74 条原始、22 条纳入分析），但受"每条视频限 3 条"与时间集中（3 天）所限，**不足以对主结论构成数据支撑，仅作定性旁证**。其余社交渠道未获得任何评论正文，报告中未做任何推测性补充。

需要区分两种性质不同的失败，避免把"被拦住"和"没去试"混为一谈：

- **被平台风控主动拦截**：贴吧（滑块验证）、知乎（403）、抖音（验证码）、小红书（IP 限制）。这四家在无头 + 无登录态的条件下确实拿不到正文，但原因是**风控**，不是"无头浏览器渲染不出来"。
- **B站 未被拦截，但被限量**：搜索与评论接口都能调用，问题不在"能不能连上"而在"单视频只给 3 条"。这是**配额限制**，不是风控拦截——两者对"下一步怎么办"的指向完全不同。
- **B站 后续若继续投入**：唯一可行方向是使用登录态（`wbi/main` 接口即可翻页），但这会用个人账号承担风控风险，且违反"不借用个人身份获取数据"的稳妥原则，本次**主动放弃**。

## 四、对报告结论的影响（必须写进报告"局限"一节）

1. **渠道单一**：主数据集（266 条）结论主要来自 iOS App Store 用户。安卓用户仅豌豆荚 9 条；社交媒体中只有 B站 拿到 22 条可用样本，且时间集中于 3 天内，**不构成对主结论的数据支撑**。社交媒体用户的观点总体仍未被覆盖。
2. **时间偏置**：App Store 接口只返回每页前 10 条，样本天然偏向"最新"和"最有帮助"，**不能用于推断长远时间趋势**。
3. **总量有限**：豆包系有效样本 79 条（清洗后），其中主 App 仅 18 条。单个产品线样本普遍低于 30 条，**产品线级别的结论只能作为方向提示，不能作为定量结论**。
4. **评分结构失真**：样本中 1★ 占比较高（因为"最有帮助/最新"排序会优先展示近期争议评论），**不可与 App Store 页面 4.66 分的总体评分做比较**。
