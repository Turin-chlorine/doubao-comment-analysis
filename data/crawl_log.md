## 二、成功渠道的技术细节

### 1. App Store 中国区（主证据源）

原计划走苹果公开的评论 RSS 接口，实测已失效：

```
GET https://itunes.apple.com/cn/rss/customerreviews/id=6459478672/sortBy=mostRecent/json
→ 返回 200，但 feed 中无任何 entry（苹果已停止该接口的评论下推）
```

改用仍可用的遗留接口：

```
GET https://itunes.apple.com/WebObjects/MZStore.woa/wa/userReviewsRow
      ?id=<appId>&displayable-kind=11&page=1&sort=<1-8>&appVersion=all
Headers: X-Apple-Store-Front: 143465-19,29
```

**该接口的关键限制**：`page` 参数**不生效**——page=1 到 page=30 返回完全相同的 10 条。因此横向扩展的唯一办法是**遍历 sort 维度**（sort=1…8 各自返回不同的 10 条），实测每个 App 可稳定获得 30–38 条去重后的唯一评论。

采集范围：豆包主 App、豆包爱学、豆包输入法，以及 DeepSeek、千问、Kimi、元宝、文心 5 款竞品。

### 2. 豌豆荚（安卓应用商店）

`https://www.wandoujia.com/apps/com.larus.nova/comment` 的评论是服务端渲染的，可直接解析 `li.normal-li` 结构。但 `?page=N` 参数同样不生效，首屏固定 10 条，页面标注总数 99 条但无可用翻页入口。

该渠道的评分只有"推荐 / 不推荐"二元选项，入库时按 5★ / 1★ 折算（已在 `comments.csv` 的 `note` 字段标注）。

## 三、失败渠道的技术细节与结论

| 渠道 | 卡在哪 | 是否有替代路径 |
|---|---|---|
| 黑猫投诉 | 首页正常（9,882 字符），但 `/search/?keywords=豆包` 返回空 DOM（2 字符）；其 API `/api/index/feed` 需要客户端生成的 `signature` 参数 | 有：需先逆向签名逻辑，或走 App 端接口。本次未做 |
| 应用宝 | 页面为纯 SPA，Network 中无任何 XHR，`document.body.innerText` 仅 51 字符 | 未知：可能需要 App 端协议 |
| 小米应用商店 | 页面正常渲染但注明"维护中"，评论区入口不可用 | 有：等维护结束或走 App 接口 |
| 华为应用市场 | 未拿到豆包的正确 appID | 有：可从华为网页版搜索页重新定位 |
| 小红书 / 抖音 / B站 / 知乎 / 贴吧 | 无头浏览器环境返回空正文或被拦截，登录态无法获取 | 有：**需人工导出**（见下） |

**结论**：本次分析的主证据来自 App Store + 豌豆荚，属于"应用商店评论"这一类渠道。社交媒体渠道（小红书 / B站 / 抖音 / 知乎）在本次技术条件下**不可自动获取**，报告中所有结论均不涉及该渠道，未做任何推测性补充。

## 四、对报告结论的影响（必须写进报告"局限"一节）

1. **渠道单一**：结论主要来自 iOS App Store 用户。安卓用户、社交媒体用户的观点未被覆盖。
2. **时间偏置**：App Store 接口只返回每页前 10 条，样本天然偏向"最新"和"最有帮助"，**不能用于推断长远时间趋势**。
3. **总量有限**：豆包系有效样本 79 条（清洗后），其中主 App 仅 18 条。单个产品线样本普遍低于 30 条，**产品线级别的结论只能作为方向提示，不能作为定量结论**。
4. **评分结构失真**：样本中 1★ 占比较高（因为"最有帮助/最新"排序会优先展示近期争议评论），**不可与 App Store 页面 4.66 分的总体评分做比较**。
